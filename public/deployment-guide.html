Architecture Selection

Why Hostinger VPS is Required for ELFAA

When ordering your hosting on Hostinger, choose KVM VPS Hosting rather than Shared Web Hosting. Here is why:

⚡

Hostinger KVM VPS

Recommended

A private virtual machine running Ubuntu Linux with full root administrative privileges.

  • ✅ Native Tesseract OCR: Install in seconds via apt install tesseract-ocr.
  • ✅ Background Workers: Run Laravel Queue & Schedule runners continuously.
  • ✅ Real-time Telemetry: High-frequency GPS ping ingestion without timeout limitations.
  • ✅ Inertia/Vite Build: Run Node.js and NPM directly on the server.
  • ✅ Full Isolation: Dedicated RAM & CPU ensure rapid OCR image analysis.
⚠️

Hostinger Shared Hosting (cPanel)

Not Recommended

Standard web hosting where server resources are shared among hundreds of websites.

  • ❌ No Root / Sudo Access: Cannot install system packages like Tesseract.
  • ❌ Restricted Shell: proc_open and exec are frequently blocked.
  • ❌ No Daemon Processes: Cannot keep persistent GPS websockets or workers alive.
  • ❌ Strict Execution Timeouts: Large document OCR analysis will hit 30s gateway timeouts.
Deployment Roadmap

Step-by-Step Hostinger VPS Deployment

Follow this exact sequence to deploy your production ELFAA instance from your GitHub repository onto a fresh Hostinger Ubuntu VPS.

1

Connect to Your Hostinger VPS via SSH

Open your local terminal (PowerShell, Command Prompt, or macOS Terminal) and connect using the IP address and password provided in your Hostinger dashboard:

# Replace with your Hostinger VPS IP address ssh root@YOUR_SERVER_IP
2

Update Packages & Install System Stack

Install Nginx, PHP 8.2 (with all required Laravel extensions), Git, Composer, and Node.js:

# Update apt package index sudo apt update && sudo apt upgrade -y # Install Nginx, Git, Unzip, and Curl sudo apt install -y nginx git unzip curl software-properties-common # Install PHP 8.2 and extensions sudo add-apt-repository ppa:ondrej/php -y sudo apt update sudo apt install -y php8.2-fpm php8.2-cli php8.2-mbstring php8.2-xml \ php8.2-curl php8.2-sqlite3 php8.2-mysql php8.2-zip php8.2-gd php8.2-intl # Install Composer globally curl -sS https://getcomposer.org/installer | php sudo mv composer.phar /usr/local/bin/composer # Install Node.js 20.x & NPM for React/Vite compilation curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - sudo apt install -y nodejs
3

Install Tesseract OCR Engine on Linux

This is where the magic happens! On Ubuntu Linux, Tesseract and the English training data are installed in one command:

# Install Tesseract OCR & language data sudo apt install -y tesseract-ocr tesseract-ocr-eng # Verify installation tesseract --version which tesseract # Expected output: /usr/bin/tesseract
ℹ️
Automatic Detection: ELFAA's TesseractOcrService.php already includes /usr/bin/tesseract in its search candidate list. You do not need to rewrite any OCR code!
4

Clone Your ELFAA Repository

Clone the project into /var/www/elfaa and set up proper permissions:

# Navigate to web root cd /var/www # Clone from your GitHub repository git clone https://github.com/zelys0725-lab/ELFAA-Car-v1.git elfaa cd /var/www/elfaa # Install PHP dependencies without dev packages composer install --no-dev --optimize-autoloader # Install frontend packages and build React production assets npm install npm run build
5

Configure Production Environment (.env)

Create your production environment file and configure database and Tesseract paths:

# Copy example environment cp .env.example .env # Generate application encryption key php artisan key:generate # Edit your .env with nano or vim nano .env

Ensure these specific values are set inside /var/www/elfaa/.env:

APP_ENV=production APP_DEBUG=false APP_URL=https://yourdomain.com TESSERACT_PATH="/usr/bin/tesseract" TESSERACT_TIMEOUT=60 # Database (SQLite is fastest for single-server, or use MySQL) DB_CONNECTION=sqlite
6

Database Migrations & Permissions

Create the database, run migrations, create storage symlinks, and grant Nginx permissions:

# For SQLite: create empty database file if not present touch database/database.sqlite # Run production migrations php artisan migrate --force # Create storage symlink for uploaded images/documents php artisan storage:link # Clear and optimize configuration cache php artisan config:cache php artisan route:cache php artisan view:cache # Set web server permissions sudo chown -R www-data:www-data /var/www/elfaa/storage /var/www/elfaa/bootstrap/cache /var/www/elfaa/database sudo chmod -R 775 /var/www/elfaa/storage /var/www/elfaa/bootstrap/cache
7

Verify OCR with Diagnostic Command

Test that the production server detects Tesseract and can process documents:

php artisan tesseract:check

You should see:

=== Tesseract OCR Diagnostic Check === 1. Configured path (.env / config): /usr/bin/tesseract [OK] Detected binary: /usr/bin/tesseract [OK] Binary file exists. [OK] Version: tesseract 5.3.x / 5.4.x [OK] Installed Languages: eng, osd === Diagnostic Complete: Tesseract OCR is working properly! ===
Web Server & Security

Nginx Virtual Host & Free Let's Encrypt SSL

Configure Nginx to serve your application securely over HTTPS with HTTP/2 and modern caching headers.

1. Create Nginx Configuration

Create a configuration file at /etc/nginx/sites-available/elfaa:

# Open file in nano sudo nano /etc/nginx/sites-available/elfaa

Paste the following optimized configuration (replace yourdomain.com with your domain):

server { listen 80; server_name yourdomain.com www.yourdomain.com; root /var/www/elfaa/public; add_header X-Frame-Options "SAMEORIGIN"; add_header X-Content-Type-Options "nosniff"; index index.php; charset utf-8; client_max_body_size 25M; location / { try_files $uri $uri/ /index.php?$query_string; } location = /favicon.ico { access_log off; log_not_found off; } location = /robots.txt { access_log off; log_not_found off; } error_page 404 /index.php; location ~ \.php$ { fastcgi_pass unix:/var/run/php/php8.2-fpm.sock; fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name; include fastcgi_params; fastcgi_hide_header X-Powered-By; } location ~ /\.(?!well-known).* { deny all; } }

2. Enable Site & Issue Free SSL Certificate

# Enable site configuration sudo ln -s /etc/nginx/sites-available/elfaa /etc/nginx/sites-enabled/ sudo rm /etc/nginx/sites-enabled/default # Test Nginx syntax sudo nginx -t # Reload Nginx sudo systemctl reload nginx # Install Certbot and obtain free SSL certificate sudo apt install -y certbot python3-certbot-nginx sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com
🔒
Automatic HTTPS: Certbot will automatically configure the SSL certificate, rewrite your Nginx configuration, and install a cronjob to renew the SSL certificate every 90 days completely free of charge.
